## 摘要

- **fit v1.0.0 综合排名第一，92.8 分（满分 100）**，领先 nginx（74.6）、Envoy（41.9）、Caddy（29.5）和 Traefik（28.9）。名次与 11-05

  （90.7 对 fit 的 93.2）和固定速率（81.4 对 89.8）上与 fit 最接近。
- **这次安全版本让 fit 在 W0 的 h2c 和 h2 上，在途 100 以上时慢了 3-5%，其他地方约 1%。**
  - fit 相对 11-05 的中位数：吞吐 -1.2%，每请求 CPU +1.5%。
  - 其他服务器没有改动，变化在 -0.3% 到 -0.8% 之间，这是两次运行之间压测机本身的漂移。
  - W0 的这部分损失超出了以往所有方案的波动范围：在途 5,000 时 h2c 自 11-03d 以来一直是每秒 339-343 万，这次是 326 万。原因是 I158，即

    这个版本，但还没有发布。
  - 在这些表里 fit 仍是 nginx 的 3.3 到 6.7 倍，所以 fit 在这些项的得分没有变化。
- **fit 仍有三处落后：**

评分、权重和方法自 11-05 以来没有变化，所以两列可以直接比较：

- **项：** 方案中的每张表是一项，即某个结果文件里的一个场景加一个协议。
- **每项得分**满分 100，由四个占该表最好者的比例加权求和：吞吐量、CPU 效率、内存效率、延迟。再乘以服务器未失败请求所占的比例。运行失败，
  或服务器无法支持该场景，得 0 分。
- **负载权重：** W1 占 25%；W0、W2、W6 各占 15%；W3、W4、W5 各占 10%。同一负载的各项平分该负载的权重。W5 更看重内存，W6 更看重 p99 延迟。
- **服务器的综合得分**是它参加的各项的加权平均。覆盖率是这些项占方案总权重的比例：方案中 Envoy 不跑 W2，Traefik 只跑 W1、W4、W5、W6。

完整的评分方法和每一项的得分见 [tables.md](tables.md#scores) 末尾。

得分是相对该表最好者的比例，所以在 fit 遥遥领先的表里，它的损失几乎不影响得分：W0 的 h2c 和 h2 慢了 3-5%，fit 的 W0 只从 99.1 降到 99.0。
在各服务器接近的表里，变化更明显：fit 的 W3 从 98.1 降到 97.4，是因为 100 连接单次请求时 Envoy 的 p99 从 2.68 降到 1.73 ms，尽管 fit 在
这张表里的名次反而升了一位。nginx 的 W6 从 83.3 降到 81.4，因为它在每秒 20 万请求时 HTTP/1.1 的 p99 从 1.68 升到 2.17 ms。

## 11-05 以来的变化

这次方案用的 fit 和 fib 相对 11-05：fit baf933e..61b5a6c4，97 个提交；fib f5b63c7..v1.7.2，68 个提交。

**fib v1.7.1 和 v1.7.2** 来自安全审查。大多数改动是限制内存或检查输入，位置都不在方案会跑到的路径上：gRPC、WebRTC、各媒体协议、SOCKS、
DTLS，以及 QUIC 乱序数据的处理。在方案路径上的改动：

- **HTTP/2**（dabe569、46af102）：逐字节检查每个请求的 `:method`、`:scheme`、`:authority` 和 `:path`，并统计同一连接整体收集的请求体大小。
  这就是 I158 的开销，也就是 W0 中 h2c 和 h2 的损失。
- **HTTP/1.1**（72294ce、938f812、678ab45）：头部或 trailer 中的裸 LF 和 obs-fold 会被拒绝，chunk 行长度有上限，请求体只扫描一遍。
- **TLS**（8492f33、20eee13、166e85f）：先检查 ticket 的 binder，再检查客户端证书链；限制 ClientHello 之前握手可以缓存的数据；CBC 的 MAC
  以常数时间累加。W3 的连接抖动全是握手，变化在 -0.3% 到 +0.1% 之间。
- **HTTP/3**（223b562、d111519、3198ae7）：按各自的语法检查伪头部；声明的请求体长度不再预先整块预留；乱序数据只保存一份。
- **连接自己的空闲超时**（27f5c88）：新 API，fit 的控制台在用。方案不跑控制台。

**fit 在 fib v1.7.1 之后的安全修复**中，在方案路径上的改动：

- 所有路由和处理器都按请求的规范化路径匹配（114dc5ec）。
- 客户端的 `Connection` 字段只列出它自己发送的字段（44aaac54）。
- 用 `_` 拼写的身份字段不能冒充 auth 设置的字段（bff8f08d）；ef2a5750 把各种拼写只列一次，让这项检查更省。
- 对已认证请求的缓存响应，只有响应明确允许时才共享（787e565f）。
- dotfile 返回 404（0d865694），静态文件查找缓存按字节数设上限（fcb77e9d）。
- 被拒绝的升级请求，其响应会以流式方式返回（5fc520b4）。

其余改动不在方案路径上：

- Admin API 走 TLS，不在 loopback 上时必须如此。
- 隧道和 LLM mesh 的链路不在 loopback 上时走 TLS。
- 隧道和 mesh 的认证。
- 按需 TLS 的数量和速率上限。
- RTSP 鉴权。
- 监听器可选启用 Multipath TCP，默认关闭。
- 日志轮转（I155-I157）。

这些加在一起，就是 fit 每请求 CPU 中位数的 +1.5%；扣除压测机自身的漂移，约多出 1%。
