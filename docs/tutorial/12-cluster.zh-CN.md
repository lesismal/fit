# 集群

[English](12-cluster.md) | [简体中文](12-cluster.zh-CN.md)

本章是教程的第 12 章，讲工作台的**集群**菜单：设置了 `admin.cluster` 的 fit 管理其他 fit。它的页面不编辑
配置（成员的凭据保存在 store 中），所以本章只列 `admin.cluster` 的参数；完整字段表在
[配置参考：Admin API](../reference/config.md#admin-api)，深入说明在[集群管理](../cluster.zh-CN.md)。

## 功能

设置了 `admin.cluster` 的 fit 是**管理端**：它把其他 fit（**成员**）的地址和管理员凭据保存在 store 的
`cluster` 节中，每隔 `poll_interval` 经成员的控制台或 Admin API 读取它的 `GET /node`、`/status` 与
`/config/check`，并把结果集中显示在**集群**菜单中。管理端不在数据路径上：无论它是否运行，成员都按各自的
配置提供服务；管理端宕机或被移除，只会失去管理能力。

管理端需要控制台（提供页面）和一个 store：`admin.store`，或 `fit run -admin` 在配置旁保存的 store。没有
store 时 `fit run` 拒绝 `admin.cluster`。凭据只写入一次，加密保存，从不出现在应答、日志或任何页面中。

菜单在控制台提供模块 `cluster` 时显示；每个页面只绘制用户的角色允许的控件（见[用户与审计](#用户与审计)）。

菜单中的页面依次为：**概览**、**节点**、**分组**、**模板**、**发布**、**漂移与告警**、**用户与审计**、
**指标**、**日志**、**证书**与 **BitTorrent**；成员自己的页面（`#/cluster/node/<name>`）、分组页、模板页、
发布页与分发页都从这些页面打开，节点切换器则打开成员自己的工作台。

## 页面与操作

### 概览

管理端最后一次读到的各成员状态，以卡片或表格显示：着色的状态（正常、错误、离线、尚未读取）及其持续时长与
原因、fit 版本、运行配置的版本与来源、一致性检查统计的不一致数、最近到期的证书与剩余天数、连接数与不可用的
上游后端，以及其 `GET /node` 的延迟。离线的成员保留其最后一次应答并注明时间。磁贴按状态计数，点击即按该
状态筛选；还可按文本、标签选择器（`env=prod, region, tier!=db, !canary`）、分组与状态筛选，按状态、名称、
延迟、证书到期、不一致数、连接数或 fit 版本排序；筛选条件保存在 URL 中。页面按轮询的频率重新读取（2 到
10 秒）。出问题的成员说明问题与处理办法，助手开启时带**问 AI**。当某个成员配有 BitTorrent 客户端、或有分发
正在进行时，筛选器上方会有一张卡片汇总整个集群的 BitTorrent 状态，并链接到 [BitTorrent](#bittorrent) 页。

### 节点

各成员的标签、URL、访问方式、凭据（只显示是否已保存）、证书的信任方式与状态，以及管理端最近的修改。
**添加节点**打开表单：名称、标签、URL、访问方式（控制台的用户名和密码，或 Admin API 的令牌），以及 `https`
时证书的信任方式（系统 CA、某个 CA 的 PEM，或固定的指纹）。**测试**按表单中的内容访问成员但不保存：显示
fit 版本、主机与节点 ID，或出错的原因，并显示成员出示的证书。不受信任的证书按指纹信任：**信任此证书**完整
显示证书、提示与成员自身的证书比对，然后把指纹固定到表单并再次测试。每个成员的行有**测试**、**信任**、
**编辑**与**删除**（先确认）。每次修改都带页面读到的 ETag；其间别处修改过会被拒绝（`412`），页面随即重新
读取。

**通过注册添加**（表单工具栏中）用于位于 NAT 之后或没有开放端口的成员：填写名称、标签、令牌有效期（留空为
24h，最长 30 天）与成员访问管理端所用的 URL，令牌与要粘贴到成员 `admin` 中的配置行只显示一次。

### 分组

一组成员：标签选择器匹配的成员、按名称指定的成员，或两者之和。页列出各分组的选择器、按名称的成员（缺失的
以琥珀色显示）、当前成员数（按状态统计）与变量数。**添加分组**在输入时预览其选中的成员。分组页显示其选择器、
成员、变量与成员状态，每个成员前有一个复选框（起初全部选中），以及**操作栏**：**重新加载**、**回滚**、
**一致性检查**、**清除缓存**与**测试**，每个操作列出将作用的成员并先确认，然后逐个成员跟踪其结果（等待中、
执行中、完成或失败及原因）。**对任意成员操作**是覆盖全部成员的同一页面。

### 模板

模板是管理端在其关联分组的成员上**拥有**的配置：整个顶层成员，以及 `listeners`、`routes`、`services`、
`upstreams` 中按名称逐个拥有的元素；`admin` 与 `schema_version` 属于成员自己。成员的**期望配置**是其自身
配置，再用模板拥有的部分替换。字符串中的**变量**按成员渲染（`${node.name}`、`${node.id}`、
`${node.hostname}`、`${node.labels.<key>}` 与分组的 `${<name>}`）。列表显示各模板的分组、顺序、拥有的部分与
按同步状态计数的成员；模板页
显示其表单与 `.conf`、`.yaml`、`.json` 文本、变量、警告，以及每个成员的同步状态与并排的值。页面下还有
**渲染结果**（某成员的当前配置与期望配置逐行并排）、**对比**（两个成员逐部分对比）与**从节点导入**。这里
不会向成员应用任何配置：应用由发布进行。

### 发布

把一次修改应用到多个成员，每次一批，每批检查通过后才进行下一批。它可以来自模板的修改或模板的草稿、成员与模板
的同步、把一个成员配置的部分复制到其他成员，或对成员配置打补丁（只有集群范围的管理员可用）。**规划**读取每个
成员、生成期望配置与逐部分的差异，并由成员通过自己的试运行检查；成员为就绪、无需修改或未就绪并说明原因，规划后
被改过的成员会被跳过。**策略**在启动时选择：`all`、`rolling`（每批 `batch_size` 或 `batch_percent`，
批间暂停 `pause_ms`）或 `canary`（第一批后等待人确认）。每批应用后进行健康检查（可达、运行的是所应用的
配置、不一致不多于发布前、5xx 比例不超过 `max_5xx_ratio`）；检查失败会停止发布并回滚。页列出历史与**新建
发布**；发布页显示每个成员的状态与差异、策略表单与**启动发布**，启动后逐批显示进度，并提供**暂停**、
**继续**、**继续发布**、**中止**与**回滚**。

### 漂移与告警

**漂移**指成员与管理端的预期不符：相对于其模板（未同步或冲突），或相对于其自身配置（一致性检查发现的差
异）。**漂移**标签页列出各成员，可只显示有漂移的，每个可看**差异**、**修复**（为其规划一次同步发布，只有人在
发布页启动后才会应用）、**修复全部未同步**与**重新加载**。**告警**标签页显示计数、正在触发的告警（带**静
默**）、等待中的与过去的告警；**规则**（`member_down`、`drift`、`rollout_failed`、`cert_expiry`、
`backends_down`、`reload_failed`）、**Webhook**（其发送情况、**测试**、编辑与删除）与**静默**各有自己的标签
页。有未静默的告警触发时，**集群**菜单的行上显示其数量，有严重告警时为红色。

### 用户与审计

管理端的控制台用户在集群上有**角色**：`viewer`（读取）、`operator`（还可运行操作与已有模板的发布）与
`admin`（还可添加、修改与删除成员及其凭据与模板、生成注册令牌、写入成员，以及修改分组与角色），分为集群范围
和按分组，取其中最高的。**用户与角色**列出每个用户、其集群范围角色、分组上的角色、助手级别与默认角色，并
**保存角色**（集群范围的管理员可用；其他人只读）。**审计日志**按用户、成员、操作与时间筛选，每个条目可打开其
差异、摘要、版本与各成员结果，并可**导出 JSON Lines**。没有角色的用户会看到提示。

### 指标

管理端从每次轮询中保存的序列（最近 360 次）：每秒的请求、4xx 与 5xx、连接数与为客户端排队的字节数，以及
应用成功与失败的配置数。一张图每个成员一条线（只绘制前 12 个成员，更多时页面会说明——按名称筛选可查看其他
成员），一张图每个分组一条线；表格列出每个成员的走势与启动以来的计数。时间范围是 30、90、180 或 360 次轮询
——默认 10 秒轮询下约 5 分钟到 1 小时，`poll_interval` 更短时也更短。

### 日志

同时追踪所选成员（最多 16 个）的日志，按时间合并；每个成员保留最新的 1,000 条，页面保留最新的 2,000 行，
**跟随**每 2 秒带着游标再次读取。可按最低级别、日志器与文本筛选，选择分组即选中其成员。

### 证书

各成员最近一次轮询读到的证书：名称、签发者、序列号、日期与剩余天数，最早到期的在前，可按文本与剩余天数
筛选；未提供证书或尚未读取的成员列在下方。

### BitTorrent

管理端即时读取的各成员 BitTorrent 角色，以及通过 BitTorrent 把种子分发给成员的分发。管理端在页面、助手或
Admin API 请求时读取各成员的 `GET /bittorrent/summary`（能力 `bittorrent.summary`），最多同时读
`max_concurrency` 个成员，每次调用受 `timeout` 限制；一次读取在 2 秒内服务所有请求，进行中的读取会被合并，
不会重复发起。页面每 5 秒重新读取；离线的成员、或早于此视图的成员（能力中没有 `bittorrent.summary`）不会被
读取，其行会说明。任何角色都可读取这一视图。

表格上方四块统计：**运行中的客户端**（客户端正在运行的成员数，以及全部成员数）、**种子**（以及多少个
出错）、**速率**（所有客户端合计的下载与上传速率）与 **Tracker**（多少个，及其种子数与对端数）。随后每个
成员一行：

| 列 | 显示什么 |
| --- | --- |
| 成员 | 名称（打开其页面），不处于正常状态时还有其状态 |
| 客户端 | **运行中** 或 **未运行**，以及它接受对端的地址；成员没有运行 `bittorrent.client` 时为**无客户端角色**；其摘要读不到时显示问题 |
| 各状态的种子 | 种子总数、各状态的数量与出错数 |
| 速率 | 它的下载与上传速率 |
| 下载 / 上传 | 它下载与上传的字节数 |
| 对端 | 它当前的对端数 |
| 已发布 | 它的各 `publish` 条目及其种子数，以及条目的错误 |
| Tracker | 其 tracker 的种子数与对端数 |
| | 它有客户端角色时的**打开**：经节点切换器打开该成员自己的 BitTorrent 页面 |

表格下方是**分发**卡片。分发把某个成员（**源**）私有发布——设置了 `private` 的 `publish` 条目，因此该种子
不会被通告到 DHT、不会与别的对端交换、也不会发给它未指定的 tracker——的种子传给其他成员，例如 LLM 节点的
模型、一次发布。每个目标以源和其他目标作为唯一的对端添加该种子，放入自己的某个分类（该分类的目录），管理端
一直跟进到每个目标都下载完整。最多 64 个目标、同时最多 2 个分发；保留最近 16 个，最新的在前，各自带状态、
源（连同发布条目与种子）以及完成、进行中、失败、取消与等待的目标数。任何角色都可读取；**新建分发**需要对源
与每个目标都有 `operator` 角色。

**新建分发**填写源（客户端发布了内容的成员）、其发布条目与种子（其 ID，或 `per_file` 条目中文件的路径；条目
只有一个种子时留空）、目标——分组的成员或下方选择的成员，或两者——目标客户端都有的分类（下载到该分类的
目录；留空则为其 `download_dir`）、完成后是否在目标上继续做种、停滞超时（分钟，留空为 10）与说明。管理端读取
源的摘要（其客户端必须运行）、发布条目与种子的 `.torrent` 文件，该种子必须是私有的；读取各目标的摘要——没有
运行客户端的目标单独失败（**无客户端**）——让每个目标添加该种子，并且每 2 秒读取各目标的进度：下载完整即完成，
客户端报错、种子被删除、或停滞超时内毫无进展（**停滞**）即失败。已有该种子的目标会被跟进，且从不删除
（**已有该种子**）。结束时，种子从被添加的目标上移除——下载完整的目标保留文件，并在**完成后继续做种**时按其
限制继续做种——失败或被取消的目标上写入的内容被删除；审计日志会记下一条 `bt.distribute`。

分发页逐个目标跟进——状态、进度、速率、对端、给其他成员使用的地址与错误——并带**取消分发**：它会先确认，
停止仍在下载的目标，并从它们上面删除该种子及已下载的内容。分发不改配置，所以不会占用成员、影响发布与操作；
管理端重启后会忘记进行中的分发，成员保留自己已有的内容。[集群管理](../cluster.zh-CN.md)页有上下限与 API，
种子本身见 [BitTorrent 章](27-bittorrent.zh-CN.md)与 [docs/bittorrent.md](../bittorrent.md)。助手的
`cluster_bittorrent` 工具读取同一视图（[第 14 章](14-assistant.zh-CN.md)）。

### 成员页与节点切换器

任何地方点击成员名称即打开其页面：管理端保存的成员与其状态，以及经管理端读取的成员自身应答（身份、运行中
的配置与重载与连接、监听、上游与后端、证书、保存的版本与一致性检查）。页眉的**节点**选择框把工作台切换到
某个成员：它的页面经管理端转发，浏览器从不持有成员的凭据；成员名出现在标题与横条中，页面以其专属颜色
标记。schema 与管理端不同的成员、以及尚未读取的成员以**只读**方式打开。

### NAT 后面的成员

主动连接管理端的成员（`admin.cluster_member`：管理端的 URL、证书指纹与只用一次的注册令牌）经这条连接被
管理，与经 HTTP 管理的成员完全相同：轮询、测试、成员页、状态与 API 都一样。其行显示**已连接**（及来源地
址）或**等待中**；**新令牌**为它生成新的注册令牌。管理端以 `admin.cluster.link_address` 开启连接监听。

## 参数

只列关键参数；完整字段表见[配置参考：Admin API](../reference/config.md#admin-api)（[中文说明](../reference/config.zh-CN.md)）。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `poll_interval` | `10s`（至少 1s） | 每个成员的 `GET /node`、`/status` 与 `/config/check` 的读取间隔 |
| `timeout` | `10s`（至少 1s） | 对成员的一次调用最长耗时：连接、应答头与整个调用 |
| `max_nodes` | 256 | 最多保存的成员数，再多则拒绝 |
| `max_concurrency` | 8 | 同时读取的成员数；页面的测试另计，最多 4 个 |
| `max_response_bytes` | 4194304（4 MiB，至少 16 KiB） | 从成员读取的最大应答 |
| `link_address` | 关闭 | 主动连接的成员到达管理端的地方（基于 TLS 的 WebSocket，其自签名证书只生成一次并保存在 store 中）；不设置则任何成员都不能注册 |
| `link_url` | 打开页面所用的主机名加端口 | 注册配置行中管理端的 URL，只能是 `wss` |
| `admins` | 无 | 无论角色如何都是集群范围管理员的控制台用户：没有管理员时的路 |

## .conf 配置

引导文件（`admin` 只在 fit 启动时生效，控制台的页面从不编辑它）：

```fit
# bootstrap file: admin is read when fit starts; the console's pages never edit it
admin {
	store {
		path /var/lib/fit/manager.store
		password_env FIT_STORE_PASSWORD
	}
	console {
		address 127.0.0.1:2020
		users {
			username admin
			password_hash "$2a$10$sKGBAOOCI4p4WWJcVCuAH.ivT8pNy2DFbs6pd8xmtNEZ/5L1SeLvm"
		}
	}
	cluster {
		poll_interval 10s
		timeout 10s
		max_nodes 256
		max_concurrency 8
		max_response_bytes 4194304
		link_address :7444
		link_url wss://manager.example.com:7444/cluster/link
		admins admin
	}
}
```

最简单的管理端是只含 `admin.cluster` 的配置，以 `fit run -admin` 运行。成员本身不需要任何配置：它的地址、
凭据与角色都在管理端的 store 中；只有位于 NAT 之后的成员需要 `admin.cluster_member`。
