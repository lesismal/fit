# 概览

[English](04-overview.md) | [简体中文](04-overview.zh-CN.md)

## 功能

概览是菜单的第一个模块，是运行中状态的只读页面，URL 为 `#/gw.overview/overview`，也是登录后打开的
页面。数据来自 Admin API 的 GET 接口，经控制台以 `/api/m/admin/status`、`/api/m/admin/config/effective`
与 `/api/m/admin/versions` 调用：fit 现在跑的是什么、每一部分来自哪里、哪里一直在出错。多数部分链接到
编辑它的页面。本页不编辑任何配置。

它每 5 秒刷新一次；顶栏的**自动刷新**复选框可关闭它（在本次使用工作台期间，直到再次勾选），**刷新**按钮
再读一次，`更新于 <时间>` 显示上次读取完成的时间。每次访问只比较本次访问中的刷新。

## 页面与操作

### 概览（`#/gw.overview/overview`）

**六个统计块**：

| 块 | 显示 |
| --- | --- |
| 配置版本 | 运行中配置的版本号、其来源（`file`、`store`、`console`、`admin`、`rollback` 等），以及多久之前应用 |
| 重载 | 启动以来成功的重载数；旁边是 `{n} 次失败`，有失败时标黄 |
| 当前连接 | 监听所在引擎上打开的连接数，包括控制台自己的连接；旁边是 `{n} 个被拒绝` |
| 路由 | 生效配置中的路由数；旁边是 `{n} 个四层服务` |
| 可用后端 | 所有上游后端合计的 `{up} / {all} 可用`，以及上游数；有不可用时标黄 |
| 证书 | 监听所提供的证书数；其中 14 天内到期（或已过期）的数量，有则标黄 |

**卡片**：

- **监听**（带**编辑**）：名称、地址、协议。
- **配置来源**：每个来源一行，按优先级顺序——来源，以及它贡献的监听、路由、上游与四层服务数。
- **被遮蔽**，只在 provider 提供的元素被配置排除时出现：其来源、元素在 provider 提供内容中的路径、
  名称，以及保留了它的来源。
- **上游健康状态**（带筛选框与指向上游页的**编辑**）：每个上游一块——名称、`{up} / {all} 可用`、在途请求数、
  设置了时的负载均衡策略与来源，有后端不可用时带**问 AI**按钮；其下是每个后端的地址、状态（可用、
  不可用（健康检查）、不可用（失败过多））、在途、成功、失败。后端在健康检查或失败把它标为不可用之前都算
  可用，所以还没有请求试过的后端也显示为可用。
- **路由**（带筛选框与指向路由页的**编辑**）：名称与优先级、监听（未指定时为 `全部`）、匹配（没有条件时为
  `全部请求`）、中间件、处理器（及其上游）、来源。筛选框按行的文字匹配，刷新后仍然有效。
- **四层服务**（带**编辑**）：名称、监听、上游、服务器名、PROXY 协议、来源。
- **证书**（带**证书**）：与 [TLS](18-tls.zh-CN.md) 页相同的证书表——监听、域名、签发者、生效与过期
  时间、序列号，以及剩余天数或已过期。
- **最近版本**（带指向版本页的**全部版本**）：所保留版本（`admin.history`，默认 10 个）中的最后 5 个，最新
  的在前，每个有版本号（运行中的带 `运行中` 标记）、应用时间与来源。

**突增**：两次刷新之间增加的错误计数——上游的失败请求、被拒绝的连接、失败的重载——在统计块上方
显示为警告行，写明在多少秒内增加了多少，并保留一分钟。每一行，以及有后端不可用的上游，都有**问 AI**按钮，以技能 `diagnose`
诊断它；对上游来说，代理到它的路由名称就是技能的输入 `route`。只有助手可用时才有这些按钮。见
[助手](14-assistant.zh-CN.md)。

### 怎样看

- **保存之后**：配置版本块显示新的版本号与来源，最近版本中它带 `运行中` 标记；任何来源的配置应用失败
  都计入重载块的 `{n} 次失败`，并显示为突增。
- **后端不可用**：可用后端块标黄；该上游的块写明是哪个后端、原因是什么（`不可用（健康检查）` 或
  `不可用（失败过多）`），其**编辑**打开上游页。
- **元素不见了**：provider 发来、表中却没有的路由或上游，可能在**被遮蔽**中：它的名称已被优先级更靠前的
  来源占用。
