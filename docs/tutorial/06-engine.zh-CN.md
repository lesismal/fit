# 引擎

[English](06-engine.md) | [简体中文](06-engine.zh-CN.md)

## 功能

引擎菜单是运行中监听的按端口视图：一级条目**引擎**（小标签**端口**），其子菜单为各监听端口，每个端口
列出它所提供的功能及编辑各项功能的页面。这个条目没有自己的页面——它展开为各端口，端口下的每个条目都是
指向其他模块页面的链接。

数据来自各编辑页面共用的配置草稿，加上 `GET /api/status` 报告的运行中地址与自动 HTTPS 生成的 `https`
与 `http` 监听；配置变化（共享草稿的 `fit:config` 事件）或刷新时菜单重建，不丢失当前页面。每个端口，
以及每个列出路由的条目，都有**问 AI**按钮，以技能 `diagnose` 诊断它，其路由名称作为技能输入 `route`。
见[助手](14-assistant.zh-CN.md)。

## 页面与操作

### 引擎

**端口**：按配置书写的顺序；未写监听且自动 HTTPS 开启时，是它生成的 `https` 与 `http` 端口（关掉重定向
时只有 `https`）；一个端口也没有——或配置无法读取——时，只有一个指向监听表单的**未配置监听**链接。端口
行显示名称与短地址（`127.0.0.1:8080` 记为 `:8080`）；完整地址、小标签、内核实际绑定的地址（与写入的不同
时）和读取失败的提示放在条目的 title 中。

端口名称下的一行小标签是它的协议与没有独立页面的功能，顺序为：协议（`HTTP/1.1`、`h2c`、`HTTP/2`、
`TCP`、`UDP`、`SOCKS`；HTTP/3 见下面的标记）、生成端口上的**自动 HTTPS**、**PROXY**、**HTTP/3**、
**按需证书**、**客户端证书**、**MPTCP**、**点播**。

**每个端口的条目**（按固定顺序，只显示端口真正具有的功能）：

1. 路由的处理器，按固定顺序：**静态文件**、**直接应答**、**FastCGI**、**媒体令牌**、**媒体页面**，然后
   是按模块 ID 列出的其他处理器——例如 [BitTorrent](27-bittorrent.zh-CN.md) 的 `bt_publish`、
   `bt_stream`、`bt_tracker`，或 [数据同步](26-sync.zh-CN.md) 的 `sync_ingest`；
2. **反向代理路由**与**正向代理路由**；
3. **缓存区**与**缓存的路由**（该端口有路由使用 `cache` 中间件时）；
4. **其他中间件**（归为一组，title 列出该端口路由用到的中间件模块）；
5. **流媒体配置**，然后各流媒体处理器的路由（**HLS 路由**、**HTTP-FLV 路由**、**WHIP 推流路由**、
   **WHEP 播放路由**），然后是**点播路由**与**频道**——该端口输出播放的频道，端口有 HLS、HTTP-FLV 或
   WHEP 路由且有频道时显示；
6. **WebRTC 配置**与各处理器的路由（**WHIP 路由**、**WHEP 路由**、**WebRTC 代理路由**）；
7. **四层服务**、**SOCKS 正向代理**（其规则在[监听](05-listeners.zh-CN.md)页编辑）、**TLS 证书**、
   **ACME 证书**、**自动 HTTPS**（端口提供 HTTP、没有 `tls` 且自动 HTTPS 开启时），以及生成的 `http`
   端口上的**重定向到 HTTPS**；
8. 最后是**端口配置**，即监听表单。

列出某处理器路由的条目带数量，点击后打开按该处理器筛选的路由页面（正向代理的路由有单独的页面）；其余条目
打开各自的页面。
