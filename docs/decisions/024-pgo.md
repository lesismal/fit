# 024: A profile-guided build of fit, from cmd/fit/default.pgo

[English](024-pgo.md) | [简体中文](024-pgo.zh-CN.md)

Status: proposed (2026-10-26).

## Context

fit's `fixed` scenario over h2c was 1.3% slower than M3's build (`1486c28`) when the benchmark
campaign of 2026-10-24 was rechecked: 3.737–3.771M requests a second against 3.79–3.82M, with the
rounds' ranges apart. The suspicion was the code's size, 6.14 MB then and 8.63 MB now, because
nothing on the request path had changed; it did not hold. A build stripped of almost every module
(6.47 MB) was *slower* than the full one by 0.9%, one without the providers was faster by only
0.6%, and instructions a request were the same in all of them (13514, 13449, 13444). What moved was
IPC: 1.516 for M3's build, 1.504 for main's, 1.492 for the stripped one.

A build with a profile collected on the benchmark host was the only one that beat both: 1.8% faster
than M3's and 3.2% faster than main's, on the same rounds.

## Decision

- **The profile is committed at `cmd/fit/default.pgo`, 94 KB.** `go build` takes a `default.pgo` in
  the main package's directory by itself (`-pgo=auto` is the default), so every build of `fit` is
  profile-guided, including the container images and the release archives, with nothing to pass.
- **It is collected where fit is measured**: the benchmark host, from `fit` serving the `fixed` and
  `site` scenarios over HTTP/1.1, h2c and h3 under the load generators of `bench/`, three 9-second
  samples merged with `go tool pprof -proto`. The profile's hot path is the same one the proxy and
  the static handler take.
- **It is refreshed when the hot path changes**, as part of the benchmark campaign that measures the
  change: a stale profile is still correct, just less of an improvement, and the numbers above are
  from this profile against the tree it was collected on.

## Consequences

- Builds are slower and the compiler's memory goes up, since it now optimizes for the profile;
  this repository's CI builds are small enough that the effect is seconds.
- The binary grows slightly, 8.63 MB to 8.73 MB of `.text`.
- The profile is a binary blob in the repository. It is 94 KB and changes with the hot path, so it
  is a normal file under review like any other, not a generated artifact to be rebuilt on every
  machine.
- A build with `-pgo=off` is a supported way to check whether a change is the profile's doing.
