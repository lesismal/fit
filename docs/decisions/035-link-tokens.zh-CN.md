# 035：隧道与 LLM 互联的签发令牌

[English](035-link-tokens.md) | [简体中文](035-link-tokens.zh-CN.md)

状态：已接受（2026-11-06）。基于 [决定 028](028-llm-and-tunnel.zh-CN.md)（各角色）以及同日决定的隧道与互联链路的
TLS（I151–I154）。

## 背景

隧道和 LLM 互联用所有成员共享的密码认证链路：隧道 hub 的 `password`（以及 `body_password`），LLM 监听的
`password` 或各角色的密码。2026-11-06 的安全审查发现了三个后果：

- **成员可以冒充另一个成员。** 持有某个角色密码的任何节点，都可以用另一个节点的名字或 ID hello，从而收到属于
  它的那部分调用，提示词也在其中；持有监听方的密码时，它还能向同一角色的其他成员冒充监听方。
- **应答拨号的对端可以离线猜测密码。** LLM 互联的拨号方以对监听方所选挑战的 HMAC 证明密码；隧道的消息体密钥
  由 PBKDF2 以 10,000 轮、在所有安装都相同的盐下派生。两者都足以让人对人工选择的密码逐个试猜。
- **密钥长期有效，且无法只为一个成员吊销**，除非在每个成员上都更换它。

如今链路在非回环地址上走 TLS 或 QUIC，路径上的攻击者已被挡在外面；剩下的问题是这个共享的、可猜的、永不过期
的密钥。对应迭代为 I159。

## 决定

- **由监听方签发的令牌。** 令牌形如 `fitt1.<id>.<secret>`：16 位十六进制的 ID，以及以无填充 base64url 编码的
  32 字节随机密钥。监听方在其成员中保存它的记录（`tunnel.hub` 的 `tokens`、LLM 角色的 `tokens`）：ID、名称、
  生成时间、可选的过期时间、可选的备注，以及密钥的哈希，从不保存密钥本身。令牌只在生成时显示一次。
- **不绑定角色。** 有效的令牌来自节点、proxy 或 hub 都一样接受：链路能做什么，仍取决于它 hello 时声明的角色
  以及监听方对该角色的规则（`allow_hub_manage`、`allow_hub_services`、`allow_proxy_services`）。绑定角色的
  令牌，会在已经决定这些事的规则之外再添一类规则。
- **成员绑定到它的第一个令牌。** 成员第一次用某个令牌注册（隧道：它的 `node/<name>` 或 `proxy/<name>`）或
  hello（互联：它的 ID）时，监听方把它绑定到该令牌，并把绑定写入令牌的 `members`；此后其他令牌对该成员一律
  拒绝，重启后也一样。吊销令牌即释放其成员：要把成员迁移到新令牌，先吊销它的旧令牌。
- **监听方保存的内容不能用来连接。** 由密钥得到：`client = HMAC-SHA256(secret, label)`，保存的哈希是
  `stored = SHA-256(client)`。拨号方以 `client XOR HMAC-SHA256(stored, "dialer to listener" | transcript)` 证明
  令牌；监听方由此还原 `client`，再用它的 SHA-256 与 `stored` 比较，与 SCRAM 的做法相同。因此拿到配置或存储
  明文的副本，并不能以某个成员的身份连接。监听方自己的证明和消息体密钥都由 `stored` 经 HKDF 派生，所以监听方
  除了哈希不需要别的；持有哈希的人能冒充监听方，而持有监听方证书和私钥的人本来就能做到。
- **握手。** 双方各加入一个新生成的 32 字节随机数：在互联中，是监听方的挑战和拨号方随后附上的随机数；在隧道中，
  是注册之前新增的一次 `challenge` 调用，携带令牌 ID 和拨号方的随机数，hub 以自己的随机数应答。记录（transcript）
  由标明协议的标签、令牌 ID、双方的随机数，以及隧道中对端的类型和名字组成，每一项之前都写有其长度。拨号方的
  证明标明“拨号方到监听方”的方向，监听方的证明标明“监听方到拨号方”并覆盖它的应答（隧道的注册应答），使用它
  自己的密钥（`server = HKDF(stored, label)`）。因此发回给发送方的证明、在另一条链路上重放的证明、或针对另一个
  随机数的证明都通不过校验。密钥有 256 位：截获的证明不泄露任何值得猜测的东西。
- **消息体密钥用 HKDF。** 设置了 `body_password`、用令牌注册的隧道链路会在 hello 中说明这一点（第 4 版，在随机
  字节之后写明令牌 ID），双方以
  `HKDF(body_key(stored) | body_password, 双方 hello 的随机字节, 方向)` 为它派生密钥：没有 PBKDF2，也没有共享
  的盐。hub 拒绝令牌与 hello 不一致的注册。用密码的链路沿用第 3 版的 PBKDF2 密钥，以便升级期间更早版本的节点
  仍能连接。
- **有效期。** 令牌在指定时间或一段时长（`30d`、`720h`）之后过期；过期的令牌在下一次握手时被拒绝，监听方在
  其过期时关闭它持有的链路，并至少每分钟检查一次（MaxSweep），以防系统时钟跳变。修改令牌的过期时间或吊销
  它都是一次配置编辑：应用时，被移除、已过期或哈希变化的令牌的链路会立即关闭。
- **三处管理，一条代码路径。** 包 `internal/linktoken` 包含令牌的密码学部分、监听方的令牌与链路登记表，以及
  通过编辑角色成员来签发、列出、修改和吊销令牌的管理器。角色的页面（隧道 hub 的“令牌”页、LLM 各角色的“连接”
  页）、Admin API（`/tokens`、`/tokens/{role}`、`/tokens/{role}/{id}`）和 `fit token list|create|expiry|revoke`
  都调用这个管理器。每次修改都记录到 `admin` 日志。令牌的最近使用、来源地址和它持有的链路属于运行时状态，不
  保存：重启后要等成员重新连接才会再出现。
- **共享密码，再保留一个版本。** 隧道 hub 的 `password` 和 LLM 监听的各密码仍然可以认证，以便成员逐个迁移。
  hub 的状态和互联的连接列表会列出仍在使用密码的成员，只要还有成员在用，页面就会给出警告；没有成员再用时，
  可以在设置中移除密码。下一版本将拒绝它。拨号方只设 `token` 或 `password` 之一，不能都设；hub 或 LLM 监听
  可以两者都没有，此时只接受令牌。

## 被否决的方案

- **绑定角色的令牌。** 链路能做什么由角色的规则决定；令牌的角色会与之重复，也挡不住一个节点冒充另一个节点，
  而成员绑定可以。
- **保存令牌本身，或把普通哈希直接用作 HMAC 密钥。** 两者都会让配置的副本成为可用来连接的凭据。SCRAM 式的
  证明让监听方保存的内容对拨号方毫无用处。
- **公钥凭据（每个成员一对密钥）。** 对配置被盗更有抵抗力，但每个成员都需要一对密钥和登记它的办法；签发令牌
  的模式适合如今生成令牌的页面和命令行，握手也仍在链路已有的帧之内完成。
- **立即只接受令牌。** 这会在升级时让所有隧道和互联中断；重叠一个版本并给出警告，成员就能逐个迁移。
- **保存最近使用时间。** 每次握手都编辑一次配置，会为没人配置的状态不断翻动配置历史和存储。
