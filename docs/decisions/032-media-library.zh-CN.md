# 032：媒体库：点播、频道与会过期的播放地址

[English](032-media-library.md) | [简体中文](032-media-library.zh-CN.md)

状态：已接受（2026-11-06）。基于 [决定 030](030-media-auth-and-pages.zh-CN.md)（媒体认证与流媒体角色）。对应
[开发计划](../dev-plan.zh-CN.md)中的 I131–I139。

## 背景

视频网站把影片和剧集存成文件，希望它们在网页上播放：点播，以及像直播一样按排期播放文件的频道，需要时再推到别的服务器；
并且只让它自己的 API 放行的观众观看，只在一段时间内有效。fit 的流媒体角色（I116）接收并提供直播流；fit 中还没有任何
东西能把文件里的媒体作为 HLS 提供，fib 也没有非分片 MP4 文件（ffmpeg、编码器和摄像机写出的形式）的读取器。一部两小时
影片的文件有几十万个采样：读取其中哪些、何时读取、保留多少，决定了 fit 能否在不阻塞 worker、内存不无限增长的前提下
提供一个媒体库。

## 决定

本轨道的原则，按约束的先后：

- **文件事先准备好，不做转码。** fit 按文件中存储的样子提供其中的编码（H.264、H.265、AV1；AAC、Opus）。不同码率的
  版本是各自独立、事先做好的文件；`scripts/` 中的脚本演示如何用 ffmpeg 制作。进程内转码不做，与流媒体角色一致。
- **任何东西都不阻塞 worker**（[规则 1](../rules.zh-CN.md)）：探测文件、读取采样表、读取分片的字节，
  都在媒体库自己的有界文件池上运行；请求以 retain 的方式等待，由文件池继续处理。目录、采样表和已构建的分片各自按字节
  设上限（[规则 11](../rules.zh-CN.md)）。
- **由网站的 API 决定谁能观看，fit 负责校验。** fit 不保存网站的任何账号。API 为一个观众、一个资源和一段有效期签发
  URL（自己签，或通过 `media_tokens`），fit 在 worker 上当场校验，不回调。
- **泄露的 URL 很快失效，也打不开别的东西。** URL 有效期短，绑定一个资源（一部作品或一个频道），需要时还绑定观众的
  地址或会话；播放器取的每个播放列表、分片、密钥和字幕都带着授权；每个主体的播放会话数有上限。
- **默认关闭**：没有 `media_library` 就不提供任何文件，也不扫描。

各迭代的决定：

- **I131，MP4 读取器放在 fib**（[fib-api-requests.md](../fib-api-requests.zh-CN.md) 中的 A64），是新包 `media/mp4`，
  而不是 `media/fmp4`。`fmp4` 读写整段放在内存中的分片，`mp4` 则通过 `io.ReaderAt` 读取文件并保留采样表；两者共用
  采样条目的读取（`fmp4.ParseSampleEntry`），轨道的编码只有一种读法。读取器在 `io.ReaderAt` 上同步运行：fit 在文件池上
  运行它。
  - `mp4.Open` 读取盒子头直到 `moov`（无论在文件开头还是末尾），读取 `moov` 中除采样表外的内容，采样表只取条目数。
    所以为目录（I132）探测一个文件只读几 KB，与文件长短无关。
  - `Track.ReadTable` 通过 16 KiB 的缓冲区一次读完一条轨道的各表，存成紧凑的 `Table`：采样大小每个采样 4 字节
    （`stz2` 为 2 字节，大小相同时为 0），每个 chunk 12 字节，每段 `stts` 16 字节，每个同步采样 4 字节，合成偏移取
    每段 `ctts` 8 字节与每个采样 4 字节中较小者；带 B 帧的 H.264 约每个采样 8.4 字节，60 fps 一小时不到 2 MB。
    `Track.TableBytes` 在读表之前就由条目数给出这个大小，媒体库的表缓存据此决定接纳或淘汰。
  - 编辑列表按播放器的方式应用：第一个实际播放的编辑之前的空编辑使轨道延后，该编辑的媒体时间在其起点呈现
    （`Track.Shift`、`Table.Time`）；因此 ffmpeg 写出的带 B 帧和 AAC 预滚采样的文件从 0 开始，与 ffprobe 显示的一致。
    之后的编辑保留给需要的调用者，不应用。
  - 分片（I133）从采样表切出：`SeekKeyframe` 和 `KeyframeBefore`/`After` 找到分片起点附近的同步采样，`Samples` 以每个
    采样恒定的开销按解码顺序遍历，`MinCTS` 给出合成偏移为负时 MPEG-TS 需要的解码提前量。
  - 读取器不信任文件中的任何内容：大小、数量和偏移都按文件和上限（`MaxTracks`、`MaxBoxes`、`MaxSampleEntries`、
    `MaxEdits`、`MaxSamples`）检查，每个 chunk 都检查是否落在文件之内，表占用的内存绝不超过文件中这些表本身字节数的
    四倍。它在 fib 的 CI 中做 fuzz。
- **I132，目录**（`media_library`）：根目录、匹配模式与扫描；带稳定 ID 的条目；按命名规则或旁置文件归组的不同码率版本；
  转成 WebVTT 的字幕；在文件池上探测，条目数、并发探测数和旁置文件大小都有上限；拒绝根目录之外的路径；探测失败的文件
  列出错误，不提供播放。
- **I133，点播**（`vod`）：fMP4 分片的 HLS，或供旧播放器的 MPEG-TS，按请求从采样表构建，在 `segment_duration` 附近的
  关键帧处切分，保存在有界缓存中；文件本身支持 `Range` 下载；`ETag` 与 `Last-Modified` 取自文件，便于 CDN 缓存分片；
  对 `vod/<library>/<id>` 使用 `media_auth` 的 `play` 动作。
- **I134，频道**（`streaming.channels`）：把条目发布进 hub，按采样时间戳在 fit 的定时器上控制节奏，条目之间时间戳连续，
  由流媒体角色的每种出口提供；`push` 目标把频道或任意流转发到外部 RTMP 或 SRT 服务器，断开后退避重连。
- **I135，会过期的播放地址**（`media_auth` 的 `url_signing`）：对资源路径前缀、过期时间、密钥 ID 和绑定字段（地址、会话）
  做 HMAC，在 worker 上校验；播放列表给播放器接下来要取的内容一份自己的授权，其有效期比 URL 的过期时间或作品时长
  （取较长者）再多 `play_grace`；`media_tokens` 签发 URL；每个主体的会话数有上限；通过轮换密钥吊销。
- **I136，加密分片**：HLS 的 AES-128，每部作品或每个频道一把由媒体库密钥派生的密钥，只提供给该资源的授权；带许可证
  服务器的 DRM 不做。
- **I137–I139**：一个视频网站示例、工作台中覆盖以上全部的页面，以及在工作台中管理文件（可续传的上传在文件池上写入
  临时文件，完整后改名就位）。

## 否决的方案

- **进程内转码。** 每路流要一个以上 CPU 核心，还需要 fit 不引入的编解码库；用 ffmpeg 事先做好的不同码率版本服务的是
  同样的播放器。
- **用 ffprobe 或 cgo 解复用器探测。** 为一个通过 `ReaderAt` 几百行就能完成的读取器，每个文件起一个进程，或引入 C
  依赖；而且两者都不在 fit 自己的池中运行。
- **把 `moov` 整个读进内存，或每个采样一个条目的采样表。** 长片的 `moov` 有几 MB，大部分是采样表；每个采样一个条目
  （偏移、大小、时间、标志）至少 24 字节，而紧凑形式约 8 字节，且其大小在读取之前无法得知。
- **读取器放在 `media/fmp4`。** 分片与整个文件的读取形态不同（内存中的字节，对比通过 `ReaderAt` 读取并保留采样表）；
  一个包同时承担两者会混淆两套 API。
- **带许可证服务器的 DRM、按观众加水印、对象存储中的媒体库。** 不在本轨道内；文件池把读取放在同一个接口之后，以便以后
  加入对象存储。
