# 006：文件 provider 采用轮询

[English](006-file-provider-polls.md) | [简体中文](006-file-provider-polls.zh-CN.md)

状态：已采纳，见 I27（2026-10-19）。

## 背景

I27 在配置文件每次变化时应用它。监视方式可以是向操作系统要事件（inotify、kqueue、ReadDirectoryChangesW，通常
通过 `fsnotify`），也可以是定期查看文件。

## 决定

- **采用轮询**：一个独立的 goroutine 每隔 `-watch-interval`（1s）查看文件的大小和修改时间，只在它们变化时读取
  文件。不引入依赖，在 fib 支持的所有系统上行为一致，而且无论文件是被原地写入，还是像编辑器和 Kubernetes ConfigMap
  那样通过重命名替换，都能发现——这两种情况在各系统上的事件各不相同。
- **文件保持不变 500ms 后才应用变化**，并且只在内容（按 SHA-256）与上次应用的不同时才应用：编辑器的多次写入只触发
  一次重载，touch 不触发。失败的配置只报告一次，下一次编辑会重新尝试。
- **用 `fit run -watch` 开启**，而不是写在配置里，因为它关系到配置从哪里来；它和 SIGHUP、Admin API 一样通过
  `admin.Configs.Apply` 应用。
- **读取文件有上限**：64 MiB。

## 影响

- 一次修改最多要等一个轮询间隔加上防抖时间才会应用，默认约 1.5s。
- 如果一次编辑后文件大小不变、修改时间又落在文件系统时间戳精度之内，要等它再次变化才会被发现；SIGHUP 仍可应用它。
