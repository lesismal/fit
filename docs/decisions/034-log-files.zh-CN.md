# 034：日志文件、切割与保留，以及日志的时区

[English](034-log-files.md) | [简体中文](034-log-files.zh-CN.md)

状态：已接受（2026-11-05）。基于 [决定 027](027-console-and-store.zh-CN.md)（workbench）与 I82–I83 的日志格式。

## 背景

fit 自身的日志和访问日志都可以写文件，而在此之前，文件只打开一次，fit 运行期间一直追加：没有东西切割它，也没有东西清理
它，改变其路径或格式还要重启。于是文件一直长到磁盘写满，运维只能在 fit 之外用重启或信号来切割。两种日志的时间也不一致：
fit 自身日志写 fib 的 `line` 格式，用本地时间；访问日志的 `json` 和 `text` 写 UTC，只有 `line` 是本地时间，且没有任何配置
可以改变。

用户要求：文件日志按时间与大小切割，按最大时间与最大大小清理，并能在 workbench 中配置；所有日志的时间默认本地，用户可自行
选择 UTC 或其他时区。对应迭代为 I155（fit 自身日志的文件）、I156（访问日志的文件走同一个写入器）和 I157（workbench 的日志
页面）。

## 决定

- **一个 fit 自己的文件写入器，不用第三方滚动库。** 包 `logs` 为每个输出路径提供有上限的文件写入器：1 MiB 的队列、
  自己的写 goroutine，切割、保留与压缩在该 goroutine 和 `internal/filepool` 上运行。一次写入把内容复制进复用的缓冲区就
  返回；队列满时拒收并计数，因此任何 logger、handler 或 fib worker 都不会等待磁盘（规则 1），慢磁盘最多占用队列那么多
  内存（规则 11）。标准库已经够用（`compress/gzip`、`time/tzdata`），不新增依赖，因此也不需要为库的选择另写决定
  （规则 14）。
- **一个路径一个写入器，两种日志共用。** `logs.Files` 由 `fit run` 创建，交给 `logs.New` 和访问日志：`log` 与
  `access_log` 写同一路径时走同一个写入器。配置校验拒绝同一路径的两组不同 `rotate` 或两个不同 `time_zone`：一个文件只在
  一个边界切割，只有一套策略。
- **`rotate` 对象即开启切割。** `log.rotate`、`log.loggers.<name>.rotate` 与 `access_log.rotate` 包含 `max_bytes`
  （1 GiB）、`interval`（关）、`max_age`（720h）、`max_files`（不限）、`max_total_bytes`（1 GiB）和 `compress`（开）。
  字段留空取默认值，设为 0 关闭该上限，因此这些字段用指针：不写 `rotate` 保持今天的单文件，fit 在启动时说明它会无限增长；
  `"rotate": {}` 是一套有界的策略。logger 写自己的文件时用自己的设置，否则用日志的。
- **切割与命名。** 会使文件超过 `max_bytes` 的写入先开始一个新文件；一次写入的时间进入比文件更晚的周期时也先开始新文件；
  两者以先到者为准。比 `max_bytes` 还大的一行自成一个文件。周期是该日志时区中从本地午夜起的整数个间隔，所以 `24h` 在午夜
  切割、`1h` 在整点切割；配置校验拒绝小于 1 秒的间隔，以及超过 24h 但不是整天数的间隔。切割出的文件命名为
  `<path>.<yyyy-mm-ddThh-mm-ss.mmm>`，即 UTC 的切割时刻，重名时加 `-1`、`-2`，压缩后加 `.gz`。文件名用 UTC，日志写哪个
  时区都保持可排序；行内时间仍按日志的时区写。
- **保留。** 打开时、每次切割后以及每十分钟清理一次，从最旧的开始：先删早于 `max_age` 的，再删超出 `max_files` 的，最后删
  到总量不超过 `max_total_bytes`。只删由该路径切割出的名字，从不删正在写的文件。压缩为 gzip 到临时文件再改名，在文件池上
  执行；失败时保留原文件，清理跳过正在压缩的文件。
- **`time_zone`：默认本地，可设 UTC 或 IANA 时区。** `log.time_zone` 与 `access_log.time_zone` 取值 `local`（不写时的
  默认）、`utc`，或 `Asia/Shanghai` 这样的 IANA 时区名。该时区既决定日志每种格式写行的时间，也决定其文件按 `interval`
  切割的边界，所以默认 `24h` 是本地午夜，设为 `utc` 则是 UTC 午夜。fit 内嵌 `time/tzdata`，没有 zoneinfo 的容器中 IANA
  名称也可用；那是标准库包而非依赖（规则 14）。访问日志的 `json` 与 `text` 原先写 UTC，现在也按该设置写，默认本地：这是
  按要求做的有意变更，其 `line` 本来就是本地时间。
- **重载时生效的内容。** `time_zone`、`rotate` 与 `compress` 重载时原地生效：写入器保留已有的文件，handler 按新时区写每条
  记录（每条消息一次转换，访问日志每秒最多一次，绝不每行一次）。文件路径与 logger 的格式仍和以前一样需要重启，workbench 与
  一致性检查都会说明；一致性检查不再报告这些已即时生效的设置。访问日志按秒缓存时间戳的做法保留。
- **不能变慢。** 新增的工作都在写入器的 goroutine 与它的池上；访问日志的一行仍在原来的位置格式化，且不分配；请求路径不新增
  锁、系统调用或分配。迭代的完成标准要求包的基准测试在压测主机上用 benchstat 对比改动前后没有回退（规则 21）。

## 未采纳

- **lumberjack 或其他滚动写入库。** 为标准库就能做的事新增依赖，还要适配它自己的队列与命名规则，而且没有 fit 的日志所需的
  时间边界切割。
- **按文件打开后经过的间隔切割。** 边界会随进程启动时间漂移；运维读日志按的是午夜与整点。
- **所有日志固定一个 UTC 时区。** 用户要求默认本地且可自行选择；写行时间的时区应当就是文件按天切割的时区，否则两者会矛盾。
- **一个全局的日志文件路径来放切割设置。** 设置属于它所切割的输出：logger 自己的文件有自己的策略，共用路径则共用一套策略。
